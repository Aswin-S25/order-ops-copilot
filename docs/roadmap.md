# Roadmap

No phase starts until the previous one has been explicitly signed off. Each phase ends with: what we built, concepts learned, decisions, tests and results, remaining issues, and what comes next.

| Phase | Goal | Key milestones | Exit criteria |
|---|---|---|---|
| **0** Architecture | Agreed design | Architecture, data model, API spec, ADRs, roadmap | Sign-off on [architecture.md](architecture.md) and the open decisions |
| **1** Foundation and DB | A running skeleton | Project layout and deps · settings (pydantic-settings, `.env`) · Docker Compose (Postgres + pgvector, Redis) · async SQLAlchemy engine · models for all core tables · Alembic baseline migration · two DB roles · structured JSON logging with request ids · `/health/live`, `/health/ready` · seed script | `docker compose up` works; migrations apply cleanly from empty and downgrade; health and DB tests pass |
| **2** Auth and isolation | Nothing leaks across users or tenants | Argon2 hashing · JWT issue and verify · `AuthContext` dependency · scopes · tenant-scoped session helper · **RLS policies + FORCE** · ownership checks · login via tenant slug | Security tests pass: buyer A can't read buyer B's order by id; tenant A can't see tenant B even with a missing app filter (RLS test); no tenant context means zero rows |
| **3** Domain services and tools | Business logic before the LLM | Order, shipment and refund services (eligibility, remainder, locking) · email outbox · mock carrier (httpx) · policy ingestion + hybrid retrieval · `ToolSpec` registry with strict schema generation · the 7 tools · REST read endpoints | Unit tests for eligibility and remainder; idempotency tests for refunds and email; the schema converter passes OpenAI strict-mode rules; retrieval is tenant-filtered |
| **4** Agent loop and minimal worker | The core AI engineering | LLM gateway (Responses API, `store=false`, verbatim item replay, reasoning items) · loop controller · parallel reads · error handling and retries · stop conditions and forced final answer · checkpoints · **Redis Streams worker (XREADGROUP/XAUTOCLAIM) + Postgres lease** · per-run event stream · SSE endpoint · first static page | End-to-end multi-tool run over SSE; every run has a stop reason; kill-the-worker test resumes without duplicate steps |
| **5** Router and planning | The cheapest correct path | Router (rules plus a structured-output classifier) · fast paths · planner for dependent multi-step tasks · LLM-call and latency measurements | A measured comparison of fast-path vs. agent latency and LLM calls |
| **6** State and memory | Long-lived context | Conversation persistence and summaries · memory extraction, retrieval and updates · recovery after restart · memory endpoints | Memory isolation and poisoning tests; a resumed run never duplicates a refund or email |
| **7** Approvals and security | The model can't bypass controls | Hash-bound approvals, maker-checker, expiry sweeper, audit · approval endpoints and inbox UI · egress allow-list · untrusted-content delimiting · injection defences · rate limiting | Security suite passes 100%: tampering, self-approval, replay, expiry, double-approve race, injection |
| **8** Evaluation and observability | Measured quality | 30+ cases × 5 trials · sandbox · metrics (success, pass-all, tool accuracy, args, state, policy, latency, tokens, cost) · failure classification · reports · CI gate | A report against the acceptance targets, with honest numbers |
| **9** Production infrastructure | Production-shaped execution | Worker hardening: concurrency limits, graceful shutdown, shared rate limits, per-user and per-tenant budgets, cancellation · traces and metrics dashboards · versioned agent config · load tests | Load test results; a zero-downtime worker restart test |
| **10** Validation and docs | Reviewable by a stranger | Final diagrams, setup guide, evaluation and security reports, performance and cost analysis, limitations, ADRs | Clone, configure, run one command, reproduce the evals |
